# GitHub Pages 개발자 포트폴리오 구현 계획

## 프로젝트 목표

GitHub Pages로 배포 가능한 개발자 포트폴리오 웹사이트를 만든다. 초기 버전은 한국어 기반의 단일 페이지 포트폴리오이며, 방문자가 개발자의 핵심 역량, 대표 프로젝트, GitHub 활동 방향, 연락 수단을 빠르게 파악할 수 있도록 구성한다.

## 기술 스택

- Vite
- React
- CSS
- GitHub Pages
- GitHub Actions

## 구현 방향

### 사이트 구조

- 첫 화면에서 프로필 요약, 역할, 핵심 소개 문구를 바로 보여준다.
- 기술 스택 섹션에서 주요 역량을 빠르게 스캔할 수 있게 정리한다.
- 프로젝트 섹션은 수동 추천 목록으로 구성한다.
- GitHub 프로필, 프로젝트 저장소, 연락 링크를 명확하게 제공한다.
- 모바일과 데스크톱 모두에서 읽기 쉬운 반응형 레이아웃을 적용한다.

### 콘텐츠 관리

- 실제 이름, GitHub 사용자명, 이메일은 초기에는 샘플 값으로 둔다.
- 프로필 정보, 기술 스택, 프로젝트 목록, 소셜 링크는 별도 설정 파일로 분리한다.
- GitHub API 자동 연동은 초기 범위에서 제외한다.
- 프로젝트 목록은 포트폴리오 품질을 위해 수동으로 큐레이션한다.

### 디자인 원칙

- 과한 랜딩페이지식 구성 대신 실무형 포트폴리오 UI를 우선한다.
- 방문자가 정보를 빠르게 비교하고 스캔할 수 있는 레이아웃을 사용한다.
- 카드의 border radius는 8px 이하로 유지한다.
- 색상은 한 계열에 치우치지 않게 구성한다.
- 화면 요소와 텍스트가 모바일/데스크톱에서 겹치지 않도록 고정 크기와 반응형 제약을 함께 사용한다.

## GitHub Pages 배포

- 배포 URL은 프로젝트 페이지 형태를 기준으로 한다.
- 기본 배포 경로는 `/codex_github_profile_page_vibe/`로 설정한다.
- Vite 설정에서 `base` 값을 GitHub Pages 프로젝트 경로에 맞춘다.
- GitHub Actions 워크플로를 추가해 `main` 브랜치 push 시 정적 빌드 결과를 Pages에 배포한다.

## 테스트 계획

- `npm run build`로 정적 빌드 성공 여부를 확인한다.
- 로컬 개발 서버 또는 preview 서버에서 주요 화면을 확인한다.
- 모바일, 태블릿, 데스크톱 폭에서 레이아웃이 깨지지 않는지 확인한다.
- GitHub Pages 프로젝트 경로 기준으로 CSS, JS, 이미지 asset 경로가 깨지지 않는지 확인한다.
- 콘텐츠 설정 파일만 수정해도 프로필, 프로젝트, 링크 정보가 UI에 반영되는지 확인한다.

## 확정된 가정사항

- 초기 버전은 단일 페이지 포트폴리오로 만든다.
- 구현 스택은 Vite React를 사용한다.
- 사이트 언어는 한국어로 한다.
- 실제 개인 정보 대신 샘플 콘텐츠로 시작한다.
- GitHub 중심 콘텐츠를 사용하지만 API 자동 연동은 하지 않는다.
- 대표 프로젝트는 수동 추천 목록으로 관리한다.
- GitHub Pages는 프로젝트 페이지 형태로 배포한다.
